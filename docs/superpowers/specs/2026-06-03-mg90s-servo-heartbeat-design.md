# MG90S 舵机心跳保持控制设计

## 目标

调整现有舵机与 Python 控制流程，实现以下行为：

- MG90S 上电后先回到复位位置。
- 只要 Python 程序持续上报有效目标，STM32 舵机板就让舵机保持在绝对 `60` 度。
- 当 Python 程序停止上报目标后，STM32 舵机板在短超时后自动回到复位位置。

## 已确认的行为

- 舵机型号：`MG90S`
- 工作位置：绝对角度 `60` 度
- 上电行为：立即回到复位角
- 信号语义：Python 在目标存在期间持续发送心跳信号
- 丢失超时：`0.1` 到 `0.2` 秒
- 已选策略：Python 持续发送 `R`，STM32 在持续收到新 `R` 时保持工作位

## 方案对比

### 方案一：心跳保持 + STM32 超时回位

Python 在目标存在时重复发送 `R`。STM32 记录最近一次收到有效 `R` 的时间戳。如果距离上次心跳还在超时窗口内，舵机就保持在 `60` 度；如果超时，则回到初始位。

推荐原因：

- 与需求完全一致
- 比边沿触发更能容忍短暂丢帧
- 回位逻辑放在 STM32 内部，不依赖 Python 再额外发停止命令

### 方案二：单次触发 + 固定保持时间

Python 只发送一次 `R`，STM32 固定保持一段时间后自动回位。

不采用原因：

- 不符合“只要持续有信息就一直保持”的目标
- 目标仍存在时也可能提前回位

### 方案三：显式开关命令

Python 发送一种命令表示工作位，另一种命令表示回位。

暂不采用原因：

- 协议复杂度更高
- 当前场景没有必要
- 一旦“停止命令”丢失，鲁棒性反而不如心跳超时方案

## 固件设计

目标文件：`2026416/Core/Src/main.c`

### 状态模型

固件只保留两个舵机状态：

- `HOME`：舵机处于复位角
- `ACTIVE`：舵机保持在 `60` 度

状态由最近收到的 `R` 是否仍在超时窗口内决定。

### 角度定义

固件中定义：

- `SERVO_HOME_ANGLE`，绝对复位角，默认 `0`
- `SERVO_ACTIVE_ANGLE`，绝对工作角，值设为 `60`
- `SERVO_SIGNAL_TIMEOUT_MS`，取 `100` 到 `200` 毫秒之间，默认建议 `150` 毫秒

### 主循环行为

1. 初始化硬件
2. 启动 PWM
3. 让舵机先回到 `SERVO_HOME_ANGLE`
4. 轮询 UART 单字节输入
5. 若收到字节 `R`：
   - 刷新 `last_signal_tick`
   - 将舵机置到 `SERVO_ACTIVE_ANGLE`
6. 独立执行超时判断：
   - 如果当前时间减去 `last_signal_tick` 超过 `SERVO_SIGNAL_TIMEOUT_MS`，则将舵机回到 `SERVO_HOME_ANGLE`

### 异常与容错

- 非 `R` 字节直接忽略
- 功能正确性不依赖 ACK
- 继续使用当前阻塞式串口轮询结构，因为现有逻辑简单，改动最小

## Python 设计

目标文件：`yolov5/yolo_serial_control2.py`

### 选择这个文件的原因

它是仓库里最新的自定义控制脚本，并且已经具备最接近目标行为的目标筛选与串口发送流程。

### 发送行为

Python 不再只在稀疏触发事件上发送一次串口命令，而是改为：

- 只要当前画面里仍存在目标，就按固定间隔持续发送 `R`
- 一旦目标消失，立即停止发送
- 回位交给 STM32 的超时逻辑处理

### 时间参数

Python 心跳间隔必须明显小于 STM32 超时：

- Python 发送间隔：约 `50ms`
- STM32 超时时间：约 `150ms`

这样可以为丢帧和串口延迟留出余量。

### 目标判断规则

保留当前目标筛选逻辑：

- 使用 YOLO 做目标检测
- 使用 ROI 做最终颜色判定
- 选择最佳红色目标

本次只改变串口发送条件：

- 之前：基于触发线事件发送
- 之后：只要当前最佳目标存在就持续发送

如果后续确实需要，也可以把触发线逻辑保留成可配置开关，但本次默认行为应当以“目标存在即保持”为准。

## 数据流

1. 摄像头画面进入 Python 主循环
2. YOLO 与颜色判定确定当前是否存在有效红色目标
3. Python 在目标存在时持续发送心跳 `R`
4. STM32 收到心跳并刷新最近一次接收时间
5. STM32 让 MG90S 保持在 `60` 度
6. 当 Python 停止发送时，STM32 超时后自动回到初始位

## 风险与缓解

### 风险：MG90S 实际机械角度存在偏差

缓解方式：

- 将角度常量保留为易调参数
- 如果 `60` 度不是实际想要的位置，只调整常量，不重写控制逻辑

### 风险：Python 发送过慢导致舵机抖动

缓解方式：

- 让心跳发送间隔明显短于 STM32 超时
- 将超时与发送间隔都定义成清晰的命名常量

### 风险：烧录的仍是旧固件

缓解方式：

- 修改后必须在 Keil/MDK 中重新编译并重新下载
